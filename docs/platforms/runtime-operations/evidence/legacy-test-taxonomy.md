# Test Strategy and Taxonomy — UniERP

> Phase J01 (Track J · Quality). **One document defining every test type, what it covers,
> where it lives, when it runs, and who owns it — so 620 tests become a portfolio rather
> than a pile.**
>
> Machine-checkable side: `docs/test-taxonomy.json` (legacy reference: `test-taxonomy.json`), generated by
> `scripts/classify-test-taxonomy.mjs` and enforced by `scripts/ci/check-test-taxonomy.mjs`,
> which fails when a test file on disk has no classification (**the exit criterion**).

## The rule that makes this a gate, not a label

> **A test that cannot fail is worse than no test, because it manufactures confidence.**

Every entry in the taxonomy therefore has a second property the manifest cannot show but this
document states: the type is determined by *what the test proves and how it can fail*, not by
where the file happens to sit. Classifying a test as `unit` when it talks to a real database, or
as `e2e` when it mocks every boundary, is a lie the next reviewer will pay for.

**Adding a test file without a manifest entry fails CI.** That is the exit criterion made
mechanical. An unclassifiable test is either reclassified or deleted with a reason — never
committed as "other".

## The taxonomy

| # | Type | What it covers | Where it lives | When it runs | Who owns it |
| :- | :--- | :------------- | :------------- | :----------- | :---------- |
| 1 | `unit` | A single unit in isolation: one service/guard/util with collaborators mocked. No real database, no network. Fails when the unit's own logic changes. | `src/**/*.spec.ts` and `*.test.ts` beside or near the code it tests | `pnpm test` on every commit, locally and in CI | The module that owns the unit (see `docs/module-tier-manifest.json`) |
| 2 | `integration` | Real database through RLS (`runWithTenantSession`, `NOBYPASSRLS`): the tenant boundary, real migrations, cross-module wiring. Fails when a migration or a query changes. | `src/**/tests/*.spec.ts` that import the real Prisma client | CI with a live `DATABASE_URL`; locally on demand | The module owning the flow under test |
| 3 | `controller` | The HTTP boundary: routing, DTO validation, status codes, `@Permissions`-guarded access → **403**. Fails when the route contract changes. | `*.controller.spec.ts` | `pnpm test` on every commit | The module owning the controller |
| 4 | `guard` | Authorisation/security guards: RBAC, ABAC, two-person control, policy engine, throttling, step-up MFA. Fails when a permission decision changes. | `src/common/guards/tests/`, `*.guard.spec.ts` | `pnpm test` on every commit | Platform / security owners (Track C, D) |
| 5 | `isolation` | Two-tenant RLS proofs: tenant B gets **zero** rows, not filtered rows. Fails when a policy is dropped or a query stops enforcing it. | `*-isolation*.spec.ts`, `*-tenant-isolation*.spec.ts`, `escape-suite` | CI with a live database; the two-tenant harness (J03) | The module whose table it guards |
| 6 | `property` | Property-based / invariant tests: generated inputs search for violations of a domain invariant (ledger always balances, stock never negative). Fails when a real edge case is found. | `*.property.spec.ts` | `pnpm test` on every commit | The module owning the invariant (Track J-II) |
| 7 | `migration` | Migration forward/backward behaviour, production-shaped data, lock and duration. Fails when a migration is unsafe. | `*migration*.spec.ts` | CI, `check-migration-safety.mjs` companion | Platform / data owners (Track J-II, J17) |
| 8 | `contract` | Consumer-driven contract (CDC): every consumer/provider pair in `cdc/expectations.json`, enforced by `cdc-harness.mjs`. Fails when a provider removes an export a consumer expects. | `cdc/**`, `*-contract*.spec.ts` | CI on the provider's repo (J05) | The provider repo's owner |
| 9 | `e2e` | Full-stack journey through the real UI and API (Playwright): every journey in `APP_FLOW.md`. Fails when a documented journey breaks. | `e2e/**`, `e2e/journeys/**` | CI on merge; nightly tagged criticality (J19) | The journey's owning module team |
| 10 | `widget` | Flutter widget/model/unit tests for the mobile client. Fails when the mobile UI or state logic changes. | `test/**/*_test.dart` | `flutter test` on every commit, CI per platform (Track I) | unierp-mobile owners |

## How files are classified

`scripts/classify-test-taxonomy.mjs` reads each test file and assigns exactly one type, in this
precedence:

1. `e2e` — under `e2e/` or imports `@playwright/test`
2. `widget` — `*.test.dart`
3. `contract` — CDC expectations or a contract test
4. `isolation` — two-tenant / escape-suite proofs
5. `property` — property-based generation
6. `migration` — migration behaviour
7. `controller` — `*.controller.spec.ts`
8. `guard` — guard / policy-engine / permissions-drift / rbac / abac
9. `integration` — real database through RLS
10. `unit` — everything else: a single unit, collaborators mocked

The precedence is deliberate: a controller test that happens to touch the database is still a
`controller` test (the route contract is what it proves); a two-tenant proof is `isolation`
before it is `integration`; a Playwright journey is `e2e` regardless of where it sits.

## What the manifest enforces

`scripts/ci/check-test-taxonomy.mjs` exits non-zero when any of these is true:

- a test file on disk has **no** entry in `test-taxonomy.json` (unclassified — add a type or
  delete the test with a reason),
- a manifest entry names a file that no longer exists (stale — remove the entry),
- a manifest entry uses a type outside the ten above.

Regenerate the manifest with `node scripts/classify-test-taxonomy.mjs --write` and commit the
result. The generated counts in `docs/test-taxonomy.json` are the honest inventory this
document makes visible: unit 481 · widget 68 · guard 19 · e2e 17 · integration 11 · contract 10
· controller 9 · isolation 3 · property 1 · migration 1.

## Absent disciplines — the pile the taxonomy must grow into

These test types the brief named do not exist yet in this tree. They are not a loophole in the
taxonomy; they are the phases that will populate it (Track J-II/J-III):

- **mutation** (J09) — a surviving mutant in financial arithmetic fails CI.
- **manual** (J20) — a maintained suite for print output, document fidelity, real payments.
- **accessibility** (J07, DONE) — `axe` in CI across every route.
- **visual regression** (J08) — baselines per component × 7 themes × 2 densities.
- **security as a discipline** (J22) — DAST, dependency/container scanning, IDOR sweeps.
- **chaos** — adversarial failure injection; **DR rehearsal** (J25) — scheduled restore.
- **load / performance** (J13, J14) — budgets per route enforced in CI, `load-tests/`.

When a phase ships one of these, it extends the ten types in this document, the `TAXONOMY` set
in `check-test-taxonomy.mjs`, and the classifier — in one commit, so the manifest never calls
a test a type nobody can run.
