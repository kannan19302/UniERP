Generated by `node scripts/inventory-coverage-padding.mjs`. Every
`*.coverage.spec.ts` file under `unierp-api/src`, with its `it()`/`test()`
count and how many of those blocks are ALWAYS-PASSING — mechanically
incapable of failing regardless of what the code under test does — the
exact D016 finding this phase measures directly rather than estimates.

A block counts as always-passing if EITHER: it contains zero `expect()`
calls at all, OR it wraps the call in `try { ...; expect(result)
.toBeDefined() } catch (e) { expect(e).toBeDefined() }` — the exact idiom
found throughout this codebase, where one branch always executes and both
only assert "is not undefined," true for nearly any return value AND any
thrown Error. It genuinely calls the method (real coverage of that line),
but cannot fail no matter what the method returns or throws.

checkout has this many today — reported as the real count, not adjusted to match).

**Known false-negative in this measurement:** a block whose only assertion is
trivially true in some OTHER shape than the two patterns above
(`expect(true).toBe(true)` with no try/catch, or a weak assertion outside
a try/catch that a real bug could still surface as an unhandled rejection)
is NOT counted above — this is a conservative floor on padding, not an
exhaustive one.
